You are building a project called **free-fast-mode**.

Goal
----
free-fast-mode is a local performance layer that makes coding agents like Claude Code and Codex run faster and cheaper.

It must **not change the agent’s intent or planning**.

Instead, it optimizes **how the agent’s chosen operations execute** through:

- batching
- caching
- deduplication
- speculation
- narrowing
- targeted execution

Think of free-fast-mode as a **query optimizer + memoization layer for coding-agent tool calls**.

Same task. Same agent. Same tools.
Just faster and cheaper.

Do NOT build a large orchestration runtime.
Do NOT build a planner.
Do NOT build a repo analysis product.

Focus on **execution acceleration**.

------------------------------------------------

Core Principle
--------------

Agents repeatedly perform expensive operations:

- reading files
- searching text
- discovering tests
- resolving related files
- summarizing context
- running test targets

free-fast-mode should expose optimized **typed operations** that perform these tasks efficiently.

Each operation supports:

- batching
- deduplication
- caching
- speculative prefetch

------------------------------------------------

Core Concept: Operation
-----------------------

Define a typed abstraction called **Operation**.

Example operations:

- read_files
- search_text
- find_symbol
- resolve_related_files
- discover_tests
- run_test_target
- summarize_outputs

Each operation should support metadata such as:

- cache key
- batchable flag
- dedupe key
- estimated cost
- speculation hints
- scope

Execution flow:

agent → operation → optimizer → execution → cache

------------------------------------------------

Optimizer Responsibilities
--------------------------

The optimizer performs four key actions:

1) COALESCE
Combine multiple small operations into larger batch operations.

Example:
read file A
read file B
read file C

→ batch read

2) REUSE
Reuse cached results when possible.

Example:
search results
file summaries
workspace metadata

3) SPECULATE
Prefetch likely next artifacts safely.

Example:
after reading a test file → prefetch related module + config

4) GATE
Prevent obviously wasteful execution patterns.

Example:
broad scans when narrower scope is known

Cache Layer
-----------

Implement a local cache with:

- operation results
- search results
- file summaries
- workspace snapshot
- test discovery results

Cache keys should consider:

- repo path
- branch if available
- HEAD SHA if available
- file fingerprints

Support invalidation when:

- files change
- branch changes
- lockfiles change
- test configs change
